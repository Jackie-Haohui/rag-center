## 2. 认证流程

### 2.1 API Key 认证

```
1. 用户在平台创建 API Key
     │
2. 原始 key 被 SHA256 哈希后存储
   key_hash = SHA256(raw_key)
   key_prefix = raw_key[:16]  (明文展示)
     │
3. 用户请求时携带:
   Authorization: Bearer <raw_key>
     │
4. 服务端认证:
   hash = SHA256(raw_key)
   api_key = ApiKeyRepository.get_active_by_hash(hash)
     │
5. 获取租户信息:
   TenantContext(tenant_id=api_key.tenant_id, ...)
```

### 2.2 安全原则

```python
# ✅ 安全设计:
# - 数据库不存明文key, 只存 hash
# - 支持 key 过期 (expires_at)
# - 支持 key 吊销 (status = "revoked")
# - 支持多条 key (方便轮换)

# ❌ 不安全做法 (本项目未采用):
# - 明文存储 API Key
# - 无过期时间
# - 单一 root key
```

## 4. 权限检查流程

### 4.1 套餐解析

```python
# app/tenant/plan_resolver.py
class PlanResolver:
    @staticmethod
    def resolve_plan(tenant: Tenant) -> PlanContext:
        plan = tenant.plan if tenant.plan in {"free", "standard", "pro"} else "free"
        preset = PLAN_PRESETS[plan]
        return PlanContext(plan=plan, features=preset.features, limits=preset.limits)
```

### 4.2 功能禁用机制

```python
# app/tenant/retrieve_policy.py
def resolve_retrieve_request(request, plan_context):
    # 1. 检查 profile 是否允许
    if request.profile not in plan_context.features.allowed_profiles:
        # 降级为默认profile
        request.profile = DEFAULT_RETRIEVE_PROFILE  # "balanced"

    # 2. 功能开关逐个检查
    rerank_reason = None
    if request.rerank_options.enabled and not plan_context.features.rerank_allowed:
        request.rerank_options.enabled = False
        rerank_reason = f"当前套餐({plan})不支持 ReRank"

    evidence_reason = None
    if request.evidence_options.enabled and not plan_context.features.evidence_allowed:
        request.evidence_options.enabled = False
        evidence_reason = f"当前套餐({plan})不支持 Evidence"

    # 3. KB数量限制
    if len(request.kb_ids) > plan_context.limits.max_kb_per_retrieve:
        raise AppError("联合检索知识库数量超过套餐限制")

    return resolved_request, TenantPolicyMetadata(...)
```

### 4.3 配额检查

```python
# app/services/quota_service.py
class QuotaService:
    def check_create_kb(self, tenant_id):
        plan = self.resolve_plan(tenant_id)
        kb_count = self.repository.count_by_tenant(tenant_id)
        if kb_count >= plan.limits.max_kb:
            raise AppError(QUOTA_EXCEEDED,
                msg=f"知识库数量已达套餐上限 ({plan.limits.max_kb})")

    def check_upload_document(self, tenant_id, kb_id):
        plan = self.resolve_plan(tenant_id)
        doc_count = self.repository.count_by_kb_id(kb_id)
        if doc_count >= plan.limits.max_documents_per_kb:
            raise AppError(QUOTA_EXCEEDED,
                msg=f"单库文档数已达上限 ({plan.limits.max_documents_per_kb})")

        processing_count = self.repository.count_processing_by_tenant(tenant_id)
        if processing_count >= plan.limits.max_processing_documents:
            raise AppError(QUOTA_EXCEEDED,
                msg=f"并发索引任务已达上限 ({plan.limits.max_processing_documents})")
```

## 5. 限流实现

### 5.1 基于 Redis 的 QPS 限流

```python
# app/services/rate_limit_service.py
def _check_qps(self, tenant_id, qps_limit):
    second = int(time())  # Unix秒
    key = f"rag:ratelimit:retrieve:{tenant_id}:{second}"
    count = int(self.redis.incr(key))
    if count == 1:
        self.redis.expire(key, 2)  # 2秒后自动清除
    if count > qps_limit:
        raise AppError(API_RATE_LIMIT, msg="检索请求过于频繁，请稍后再试")

# Free:    每秒3次 → 超过3次/秒即拒绝
# Standard: 每秒10次
# Pro:     每秒50次
```

### 5.2 日配额限流

```python
def _check_daily_quota(self, tenant_id, daily_limit):
    day = datetime.now(UTC).strftime("%Y%m%d")
    key = f"rag:quota:retrieve:daily:{tenant_id}:{day}"
    count = int(self.redis.get(key) or 0)
    if count >= daily_limit:
        raise AppError(QUOTA_EXCEEDED, msg="日检索量已达上限")

# Free:    500次/天
# Standard: 5000次/天
# Pro:     10万次/天
```

### 5.3 检索成功后计数

```python
def record_retrieve_success(self, tenant_id):
    daily_key = f"rag:quota:retrieve:daily:{tenant_id}:{YYYYMMDD}"
    pipe = self.redis.pipeline()
    pipe.incr(daily_key)
    pipe.expire(daily_key, seconds_until_end_of_day + 3600)  # 冗余过期
```

## 9. 最佳实践

### 安全

```
✅ 定期轮换 API Key
✅ 为不同环境创建不同 Key (dev/staging/prod)
✅ 设置合理的过期时间
✅ 不要在代码中硬编码 Key, 用环境变量
```

### 套餐选择

```
Startup/MVP →     Free: 快速验证 RAG 可行性
Growing     →     Standard: 混合检索, 5个KB够用
Enterprise  →     Pro: Research + 所有高级功能
```

### 监控

```
关注指标:
  - QPS 使用率 (接近上限时考虑升级)
  - 日配额消耗 (设置告警)
  - 文档处理失败率 (检查 error_message)
  - 检索延迟 (关注 degraded 标记)
```
