# 03 - 文档上传与解析

> **Document Upload & Parsing**  
> rag-center 支持多种文档格式的自动识别和解析，将原始文件转换为适合 RAG 检索的结构化文本。

---

## 1. 支持的文档格式

| 格式 | 扩展名 | 解析器 | 输出格式 |
|------|--------|--------|----------|
| Markdown | `.md`, `.markdown` | `MarkdownParser` | 原文 (source_type=markdown) |
| 纯文本 | `.txt` | `MarkdownParser` | 原文 (source_type=text) |
| PDF | `.pdf` | `PdfParser` | 提取文字后转Markdown |
| Word | `.docx` | `DocxParser` | 提取文字+结构后转Markdown |

## 2. 上传文档

### 2.1 直接传文本（JSON 方式）

```bash
POST /api/v1/documents/upload
Authorization: Bearer <your_api_key>
Content-Type: application/json

{
    "kb_id": "kb-uuid-here",
    "user_id": "user_001",
    "title": "公司考勤管理制度",
    "content": "# 第一章 总则\n\n第一条 为规范..."
}
```

### 2.2 上传文件（multipart/form-data）

```bash
POST /api/v1/documents/upload
Authorization: Bearer <your_api_key>
Content-Type: multipart/form-data

字段:
  kb_id: "kb-uuid-here"
  file:  <选择文件>
  title: "可选标题"  (不填则用文件名)
```

### 2.3 文件大小限制

```python
# 通过配置项 document_max_size_mb 控制
# 默认建议 10MB
if len(file_bytes) > settings.document_max_size_mb * 1024 * 1024:
    raise AppError(msg="文件大小超过限制")
```

## 3. 文档上传全流程

```
┌─────────────────────────────────────────────────────────┐
│                    POST /documents/upload                 │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ① 请求到达                                              │
│     ├── 判断 Content-Type: JSON 还是 Multipart            │
│     ├── 文件格式: validate_upload_extension(filename)    │
│     └── 文件大小检查                                      │
│                                                          │
│  ② 配额检查 (QuotaService)                               │
│     ├── 知识库文档数是否超限?                              │
│     └── 并发处理任务数是否超限?                            │
│                                                          │
│  ③ 保存文件 (仅文件上传)                                  │
│     └── save_document_file(tenant_id, doc_id, filename)  │
│         路径: {document_storage_path}/{tenant_id}/{doc_id}│
│                                                          │
│  ④ 创建数据库记录                                        │
│     ├── Document(id, tenant_id, kb_id, title, content)   │
│     └── status = PROCESSING (⚠️ 处理中)                   │
│                                                          │
│  ⑤ 投递异步任务                                          │
│     └── index_document_task.delay(document.id)           │
│         ↑ Celery Worker 异步执行                          │
│                                                          │
│  ⑥ 立即返回                                              │
│     └── { document_id, kb_id, status: 3, chunk_count: 0 }│
└─────────────────────────────────────────────────────────┘
```

### 关键代码

```python
# app/services/document_service.py
async def upload_file(self, tenant_id, *, kb_id, title, filename, file_bytes):
    # 1. 校验扩展名
    validate_upload_extension(filename)  # 只允许 .md/.txt/.pdf/.docx

    # 2. 大小检查
    if len(file_bytes) > settings.document_max_size_mb * 1024 * 1024:
        raise AppError("文件大小超过限制")

    # 3. 配额检查
    QuotaService.check_upload_document(tenant_id, kb_id)

    # 4. 保存文件到磁盘
    source_file_path = save_document_file(tenant_id, document_id, filename, file_bytes)

    # 5. 创建数据库记录 (status=PROCESSING)
    document = indexing_service.create_file_document_record(
        tenant_id, kb_id=kb_id, title=document_title,
        source_file_path=source_file_path, source_filename=filename,
        document_id=document_id,
    )

    # 6. 投递Celery异步任务
    index_document_task.delay(document.id)

    # 7. 立即返回处理中状态
    return UploadDocumentData(document_id=document.id, status=PROCESSING, chunk_count=0)
```

## 4. 文档解析 (Ingestion)

### 4.1 解析器注册与选择

```python
# app/providers/parsers/registry.py
def get_document_parser(filename: str) -> DocumentParser:
    parsers = [DocxParser(), PdfParser(), MarkdownParser()]
    for parser in parsers:
        if parser.supports(filename):  # 按扩展名匹配
            return parser
    raise AppError("不支持的文档格式")
```

### 4.2 Markdown 解析器

```python
# app/providers/parsers/markdown.py
class MarkdownParser(DocumentParser):
    def supports(self, filename, mime_type=None):
        return Path(filename).suffix.lower() in {".md", ".txt", ".markdown"}

    async def parse(self, file_bytes, *, filename):
        text = file_bytes.decode("utf-8", errors="replace")
        text = text.replace("\r\n", "\n").strip()
        source_type = "markdown" if filename.endswith((".md", ".markdown")) else "text"
        return ParsedDocument(content=text, source_type=source_type)
```

## 5. 异步索引任务

上传后，真正的解析和索引工作在 Celery Worker 中异步执行。

```python
# app/tasks/indexing.py
@celery_app.task(bind=True, max_retries=2, default_retry_delay=10)
def index_document_task(self, document_id, reparse=False):
    db = SessionLocal()  # Worker中独立数据库连接
    try:
        service = create_indexing_service(db)
        chunk_count = asyncio.run(
            service.index_existing_document(document_id, reparse=reparse)
        )
    except Exception as exc:
        if 可重试错误 and 还有重试次数:
            raise self.retry(exc=exc)  # 重新入队, 10秒后重试
        else:
            _mark_document_failed(db, document_id, str(exc))  # 标记失败
    finally:
        db.close()
```

### 可重试的错误类型

```python
RETRYABLE_ERROR_CODES = {
    ErrorCode.API_TIMEOUT,       # Embedding API 超时
    ErrorCode.API_REQUEST_ERROR, # API 临时故障
    ErrorCode.EMBEDDING_FAILED,  # 向量化失败
    ErrorCode.SYSTEM_BUSY,       # 系统繁忙
}
# 也包括网络错误: httpx.TimeoutException, ConnectionError 等
```

## 6. 文档状态管理

```python
# app/utils/status.py
class DocumentStatus:
    SUCCESS = 1      # 索引成功，可检索
    FAILED = 2       # 索引失败，不可检索
    PROCESSING = 3   # 正在处理中，不可检索
```

### 状态流转

```
创建记录 → PROCESSING (3)
              │
        ┌─────┴─────┐
        ▼            ▼
    SUCCESS (1)   FAILED (2)
        │            │
        └──重新索引──┘  (POST /documents/{id}/reindex)
              │
              ▼
         PROCESSING → SUCCESS/FAILED
```

## 7. 文档查询与删除

### 查询详情

```bash
GET /api/v1/documents/{document_id}
```

返回 chunk_count、status、error_message 等信息。

### 删除文档

```bash
DELETE /api/v1/documents/{document_id}
```

- 删除前检查：文档不能处于 PROCESSING 状态
- 级联删除：Document → Chunks → Vector Store → Relations
- 需要 IndexVersion 不在 building 状态

### 重新索引

```bash
POST /api/v1/documents/{document_id}/reindex?reparse=true
```

- `reparse=true`：重新解析原文件（适用于文件更新后）
- `reparse=false`：用已存 content 重新分块+向量化

## 8. 最佳实践

| 场景 | 建议 |
|------|------|
| **文档命名** | 用有意义的标题，LLM 会用到文档标题 |
| **文件大小** | 建议单文件 < 5MB，超大文件拆分上传 |
| **Markdown 格式** | 推荐用 Markdown 编写，保留完整标题层级 |
| **PDF 质量** | 避免扫描版PDF（无文字层），建议用原生PDF |
| **批量上传** | 注意并发处理配额，按批次上传 |
| **错误处理** | 定期检查 FAILED 状态的文档，查看 error_message |
