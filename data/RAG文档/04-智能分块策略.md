# 04 - 智能分块策略

> **Chunking Strategy**  
> 分块（Chunking）是 RAG 系统中最关键也最容易掉坑的环节。rag-center 采用结构感知的 Markdown 分块器，远比简单的字符切割更智能。

---

## 1. 为什么分块很重要？

### 1.1 分块过粗的问题

```
文档: 10000字的人力资源手册
分块: 每块5000字

问题:
- 检索到的块包含太多无关内容，LLM 难以聚焦
- Embedding 向量被稀释，语义精度下降
- 返回结果过大，超出 LLM 上下文窗口
```

### 1.2 分块过细的问题

```
文档: 10000字的人力资源手册
分块: 每块50字

问题:
- 上下文断裂，单独一个句子难以理解
- "参照前条规定" 这类引用失效
- 检索结果碎片化，需要多次检索凑齐信息
```

### 1.3 rag-center 的解决方案

```
✅ 按文档结构分块（标题层级 + 段落边界）
✅ 每个块尽量完整表达一个概念
✅ 保留标题路径供 LLM 理解上下文
✅ 支持相邻块扩展和引用图补充
```

## 2. MarkdownStructuredSplitter 设计

### 2.1 核心代码位置

```
app/utils/markdown_splitter.py   ← 565行完整分块逻辑
app/utils/text_splitter.py       ← 简单降级方案
```

### 2.2 分块流程

```
原始文档 (Markdown 文本)
        │
        ▼ _split_into_sections()
┌───────────────────────────────────┐
│  识别所有标题行 (# ## ### ...)      │
│  构建标题堆栈, 追踪层级关系          │
│  将文档切分为 Section 列表          │
│  每个 Section: {标题, 标题路径, 正文}│
└───────────────────────────────────┘
        │
        ▼ _chunk_section()
┌───────────────────────────────────┐
│  对每个 Section:                   │
│    _parse_blocks() → 识别块类型     │
│      代码块(fence) / 表格(table)   │
│      列表(list) / 段落(prose)      │
│                                   │
│    _chunk_prose_block() → 按段落切 │
│    _chunk_table() → 表头摘要+分页  │
│    _chunk_code() → 按长度切分      │
└───────────────────────────────────┘
        │
        ▼ _merge_section_pieces()
┌───────────────────────────────────┐
│  合并过小的相邻块 (≤ chunk_size)    │
│  引用指针块(> 关联规则) 特殊处理    │
│  去重: 同一section内相同content跳过  │
│  分配: section_id, order_index     │
└───────────────────────────────────┘
```

## 3. 块类型识别

分块器能自动识别并区别处理 4 种内容类型：

### 3.1 普通段落 (prose)

```markdown
## 考勤制度

公司实行弹性工作制，核心工作时间为 10:00-16:00。
员工每日需保证不少于 8 小时工作时间。

对于特殊岗位，经部门负责人审批后可采用固定班制。
```

→ 按段落边界合并，尽量保持每个 chunk 在 chunk_size 以内

### 3.2 代码块 (code)

````markdown
```python
def calculate_overtime(hours, rate):
    if hours <= 40:
        return 0
    return (hours - 40) * rate * 1.5
```
````

→ 代码块整体保留不被拆分；超长的按字符切分

### 3.3 表格 (table)

```markdown
| 职级 | 年假天数 | 病假天数 |
|------|---------|---------|
| P1-P3 | 5 | 5 |
| P4-P6 | 10 | 7 |
| P7+ | 15 | 10 |
```

→ 自动生成表头摘要 `【表头】职级 | 年假天数 | 病假天数`
→ 每 `table_max_rows_per_chunk` 行一组，每组包含表头

### 3.4 列表 (list)

```markdown
- 第一步：填写请假申请表
- 第二步：直属领导审批
- 第三步：HR 备案
```

→ 列表作为一个整体处理，保持逻辑完整性

## 4. 引用指针的识别

### 4.1 什么是引用指针？

某些文档中的章节只包含对其他部分的引用，本身信息量很低：

```markdown
### 3.5 加班费计算

> 关联规则
> 详见第二章薪酬结构
> 参照第15条加班定义
```

### 4.2 处理策略

```python
# app/utils/markdown_splitter.py
def is_reference_pointer_content(content):
    lines = content.strip().split("\n")
    return all(line.startswith("> 关联规则") for line in lines)
```

- 引用指针块被标记为 `chunk_type = "reference_pointer"`
- **零向量存储**（不参与语义检索，避免误命中）
- 合并到相邻块中，为上下文提供引用线索
- 单独在 `chunk_relations` 表中建立引用边

## 5. Chunk 元数据

每个 chunk 携带丰富的元数据，供检索和生成阶段使用：

```python
# 每个 SplitPiece 的结构
{
    "text": "加班费按基本工资的 1.5 倍计算...",
    "metadata": {
        "chunk_type": "prose",           # prose/code/table/list/reference_pointer
        "heading_path": "薪酬/加班/加班费计算",  # 完整标题路径
        "heading_level": 3,              # 标题层级
        "parser": "markdown",            # 来源解析器
        "section_id": "uuid5-abc123",   # 稳定章节ID
        "parent_section_id": "uuid5-xyz456",  # 父级章节ID
        "order_index": 15,              # 章节内顺序
        "table_part": 2,                # 表格分页编号 (仅表格)
    }
}
```

### 稳定 section_id 的生成

```python
def stable_section_id(document_id, index_version, heading_path):
    section_key = heading_path.strip() or "__document_root__"
    return uuid5(NAMESPACE_URL, f"rag-center:{document_id}:{index_version}:{section_key}")
```

- 基于 **UUID5 + 命名空间URL** 算法
- 相同的文档+版本+标题路径 → 必定生成相同ID
- 即使重新索引，section_id 不变
- 支持跨文档引用和引用图追踪

## 6. 检索文本增强 (v2)

### v1 vs v2 检索文本对比

```
v1 (直接用content):
"加班费按基本工资的 1.5 倍计算，工作日超过 8 小时部分..."

v2 (增强后的retrieval_text):
"文档：公司薪酬管理制度
章节：薪酬结构 > 加班 > 加班费计算
正文：加班费按基本工资的 1.5 倍计算，工作日超过 8 小时部分..."
```

**增强效果**：
- 向量检索时，标题和章节路径也参与相似度计算
- 检索 "加班费怎么算" 时，因为 `retrieval_text` 包含 "加班" "加班费" 等词，命中率更高
- LLM 直接看到来源信息，减少幻觉

### 代码实现

```python
def build_retrieval_text(*, title, heading_path, content):
    lines = [f"文档：{title.strip()}"]
    if heading_path.strip():
        lines.append(f"章节：{heading_path.replace('/', ' > ')}")
    lines.append(f"正文：{content.strip()}")
    return "\n".join(lines)
```

## 7. 分块参数配置

```python
# 关键参数配置
settings.chunk_size = 1024         # 每个chunk最大字符数
settings.chunk_overlap = 128       # 重叠字符数 (字符切割时)
settings.table_max_rows_per_chunk = 10  # 表格每批最大行数
```

### 参数调优建议

| 场景 | chunk_size | chunk_overlap | 说明 |
|------|:----------:|:-------------:|------|
| FAQ 短问答 | 256-512 | 64 | 小块更精准 |
| 技术文档 | 1024-1536 | 128 | 平衡 |
| 法律/合同 | 1536-2048 | 256 | 避免条款断裂 |
| 长篇小说 | 2048+ | 256 | 保持段落完整 |

## 8. 低信息量过滤

```python
def is_low_information_content(content, heading=None):
    # 空内容或纯分割线
    if not content or HORIZONTAL_RULE_RE.match(content):
        return True

    # 去除 Markdown 标记后无有效字符
    plain = strip_markdown(content)
    if not plain or not CONTENT_CHAR_RE.search(plain):
        return True

    # 纯编号行 (如 "1." "一、")
    if NUMBERING_ONLY_RE.fullmatch(plain):
        return True

    # 正文与标题完全相同 (纯标题无内容)
    if heading and normalize(plain) == normalize(heading):
        return True

    return False
```
