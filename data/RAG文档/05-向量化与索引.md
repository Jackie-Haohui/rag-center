# 05 - 向量化与索引

> **Embedding & Indexing**  
> 向量化将文本转为高维数学向量，使 "语义相似" 可以用数学计算。索引将向量高效存储并支持快速检索。

---

## 1. 向量化（Embedding）原理

### 1.1 什么是 Embedding？

```
文本: "员工加班费如何计算？"
  │
  ▼ Embedding 模型 (如 text-embedding-3-small)
  │
  ▼ 输出向量 (1024维浮点数)
[-0.0234, 0.0192, 0.0031, ..., -0.0145, 0.0087]
```

- 语义相似的文本 → 向量距离近
- 语义无关的文本 → 向量距离远
- 维度越高，表达能力越强，但存储和计算成本越大

### 1.2 rag-center 的 Embedding 抽象

```python
# app/providers/embedding/base.py
class EmbeddingProvider(ABC):
    @abstractmethod
    async def embed_texts(self, texts: list[str]) -> list[list[float]]:
        """批量文本 → 批量向量"""

    @abstractmethod
    async def embed_query(self, query: str) -> list[float]:
        """单个查询 → 单个向量"""
```

目前使用 `OpenAICompatibleEmbeddingProvider`，支持任何兼容 OpenAI Embedding API 的服务。

## 2. 索引全流程

```
文档 → 分块 → 向量化 → 写入 pgvector + Elasticsearch

具体步骤:
┌────────────────────────────────────────────┐
│ 1. text_splitter.split(content)            │
│    输入: 完整 Markdown 文档                 │
│    输出: [SplitPiece, SplitPiece, ...]     │
│    分类: 普通块(searchable) + 指针块(pointer)│
├────────────────────────────────────────────┤
│ 2. build_retrieval_text()   [v2]           │
│    "文档：xxx\n章节：A>B\n正文：xxx"         │
├────────────────────────────────────────────┤
│ 3. embedding_provider.embed_texts(texts)   │
│    调用 OpenAI Embedding API               │
│    输入: ["检索文本1", "检索文本2", ...]    │
│    输出: [[0.01, 0.02, ...], [...], ...]   │
├────────────────────────────────────────────┤
│ 4. vector_store.add_chunks(chunks)         │
│    写入 PostgreSQL pgvector 扩展           │
│    每条: {chunk_id, content, embedding,    │
│            metadata, section_id, ...}      │
├────────────────────────────────────────────┤
│ 5. keyword_search_provider.add_chunks()    │
│    写入 Elasticsearch 倒排索引 (可选)       │
│    用于 BM25 关键词检索                    │
└────────────────────────────────────────────┘
```

### 索引核心代码

```python
# app/services/indexing_service.py
async def _index_document_content(self, document, *, index_version):
    # 1. 分块
    pieces = self.text_splitter.split(
        document.content,
        document_id=document.id,
        index_version=index_version,
    )
    # 分类：普通块 vs 指针块
    searchable_pieces = [p for p in pieces if p.metadata.get("chunk_type") != "reference_pointer"]
    pointer_pieces = [p for p in pieces if p.metadata.get("chunk_type") == "reference_pointer"]

    # 2. 构建增强检索文本 (v2)
    retrieval_texts = [build_retrieval_text(title, heading_path, content)
                       for piece in searchable_pieces]

    # 3. 批量向量化
    embeddings = await self.embedding_provider.embed_texts(retrieval_texts)

    # 4. 写入向量数据库
    searchable_chunks = []
    for i, piece in enumerate(searchable_pieces):
        searchable_chunks.append({
            "chunk_id": uuid,
            "tenant_id": document.tenant_id,
            "kb_id": document.kb_id,
            "content": piece.text,
            "retrieval_text": retrieval_texts[i],      # v2增强文本
            "index_version": index_version,
            "section_id": section_id,
            "parent_section_id": parent_section_id,
            "order_index": order_index,
            "metadata": {...},
            "embedding": embeddings[i],                 # 向量
        })

    await self.vector_store.add_chunks(searchable_chunks)

    # 5. 写入关键词索引 (Elasticsearch)
    if self.keyword_search_provider:
        await self.keyword_search_provider.add_chunks(searchable_chunks)

    # 6. 引用指针块: 零向量存储
    for piece in pointer_pieces:
        chunk_repository.add(Chunk(..., embedding=[0.0]*dimensions))
```

## 3. pgvector 向量存储

### 3.1 为什么选 pgvector？

| 对比维度 | pgvector | Milvus | Pinecone |
|---------|:--------:|:------:|:--------:|
| 部署复杂度 | ✅ 低（已在用PG） | 中 | 低（SaaS） |
| 与结构化数据关联 | ✅ JOIN 自如 | 需要应用层 | 完全分离 |
| 规模上限 | 百万级 | 十亿级 | 按量付费 |
| 运维成本 | ✅ 低 | 高 | 按量付费 |
| 事务支持 | ✅ ACID | ❌ | ❌ |

### 3.2 数据库中的 Chunk 表

```sql
-- 实际数据库表结构
CREATE TABLE chunks (
    id VARCHAR(36) PRIMARY KEY,
    tenant_id VARCHAR(128) NOT NULL,
    kb_id VARCHAR(36) REFERENCES knowledge_bases(id),
    document_id VARCHAR(36) REFERENCES documents(id),
    title VARCHAR(255) NOT NULL,
    content TEXT NOT NULL,
    retrieval_text TEXT,              -- v2增强文本
    index_version VARCHAR(32) NOT NULL DEFAULT 'v2',
    section_id VARCHAR(64),
    parent_section_id VARCHAR(64),
    order_index INTEGER,
    metadata JSONB NOT NULL DEFAULT '{}',
    embedding vector(1024),           -- pgvector 扩展类型, 1024维
    created_at TIMESTAMPTZ
);

-- 向量索引 (IVFFlat 或 HNSW)
CREATE INDEX ON chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

### 3.3 向量检索实现

```python
# app/providers/vectorstores/pgvector.py
async def similarity_search_scope(self, query_vector, *, tenant_id, index_versions, top_k):
    # 计算余弦距离
    distance = Chunk.embedding.cosine_distance(query_vector).label("distance")

    # 构建多KB+版本过滤条件
    version_scope = or_(
        *[and_(Chunk.kb_id == kb_id, Chunk.index_version == version)
          for kb_id, version in index_versions.items()]
    )

    # 执行查询
    stmt = select(Chunk, distance).where(
        Chunk.tenant_id == tenant_id,       # 租户隔离
        version_scope,                       # KB+版本过滤
        # 排除引用指针
        or_(Chunk.metadata_["chunk_type"].astext.is_(None),
            Chunk.metadata_["chunk_type"].astext != "reference_pointer")
    ).order_by(distance).limit(top_k)

    rows = db.execute(stmt).all()

    # 距离 → 相似度分数
    return [{"chunk_id": chunk.id, "content": chunk.content,
             "score": 1.0 - float(distance_val), ...}
            for chunk, distance_val in rows]
```

### 3.4 余弦距离 vs 余弦相似度

```
cosine_distance(A, B) = 1 - cosine_similarity(A, B)

取值范围: [0, 2]
  0   → 完全相同方向  (最相似)
  1   → 正交           (无关)
  2   → 完全相反方向   (最不相似)

我们转换为 score = 1.0 - distance, 范围 [-1, 1]
  score → 1.0: 最相似
  score → 0.0: 不相关
  score → -1.0: 语义相反 (极少出现)
```

## 4. 关键词检索 (Elasticsearch)

### 4.1 BM25 算法简介

BM25 是经典的关键词匹配算法，与向量检索互补：

| 检索类型 | 优势 | 劣势 |
|---------|------|------|
| **向量检索** | 理解同义词/近义表达 | 对精确词匹配不敏感 |
| **BM25** | 精确匹配专有名词/编号 | 不理解语义变化 |

### 4.2 配置

```python
# settings
keyword_search_provider = "elasticsearch"  # 启用关键词检索
# 或设为 None 来禁用
```

## 5. 检索时的向量化

与索引时不同，检索时只需向量化查询文本：

```python
# app/services/rag_service.py
async def _run_vector_scope_branch(self, *, tenant_id, index_versions, search_query, top_k):
    # 1. 查询向量化 (1次API调用)
    query_vector = await self.embedding_provider.embed_query(search_query)

    # 2. pgvector 检索 (数据库内计算)
    chunks = await self.vector_store.similarity_search_scope(
        query_vector,
        tenant_id=tenant_id,
        index_versions=index_versions,
        top_k=top_k,
    )

    return RetrievalBranchResult(source="vector", chunks=chunks, ...)
```

## 6. 性能优化

### 6.1 批量向量化

```python
# 一次批量处理多个chunk，减少API调用次数
embeddings = await self.embedding_provider.embed_texts(texts)  # 批量
# 而不是:
# for text in texts:
#     embedding = await embed_query(text)  # 逐个调用，慢!
```

### 6.2 pgvector 索引选择

```sql
-- IVFFlat: 构建快, 适合中等规模, 需要预训练lists
CREATE INDEX ON chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

-- HNSW: 查询更快, 构建慢, 适合大规模
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
```

### 6.3 配置建议

| 参数 | 建议值 | 说明 |
|------|:------:|------|
| embedding_dimensions | 1024 | text-embedding-3-small |
| 批量大小 | 20-50 | 每次API调用处理的文本数 |
| top_k (检索) | 5-20 | 返回结果数量 |
