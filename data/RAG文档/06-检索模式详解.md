## 1. 三种检索模式

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  vector  │    │   bm25   │    │  hybrid  │
│ 语义检索  │    │ 关键词检索 │    │ 混合检索  │
├──────────┤    ├──────────┤    ├──────────┤
│ Embedding│    │Elastic-  │    │ vector + │
│ +pgvector│    │ search   │    │  bm25    │
│          │    │          │    │ 并联+RRF │
└──────────┘    └──────────┘    └──────────┘
```

## 2. Vector 模式 - 纯语义检索

### 原理

```
query: "加班费怎么计算"
         │
         ▼ Embedding
    向量 [0.01, -0.02, ...]
         │
         ▼ pgvector cosine_distance
    ┌─────────────────────────────────┐
    │ chunk_1: score=0.92  ← 最相关   │
    │ chunk_2: score=0.87             │
    │ chunk_3: score=0.81             │
    │ chunk_4: score=0.75             │
    │ ...                             │
    └─────────────────────────────────┘
```

### 特点

| 维度 | 评价 |
|------|------|
| 速度 | ⚡ 最快（1次 Embedding API + 1次数据库查询） |
| 语义理解 | ✅ 强（能理解 "加班费" ≈ "加班报酬" ≈ "OT pay"） |
| 精确匹配 | ❌ 弱（对职级编号 "P7"、"第15条" 不敏感） |
| 资源消耗 | 低 |

### 适用场景

- 快速原型验证
- 实时对话机器人
- 查询以自然语言描述为主
- Free 套餐用户（唯一可用模式）

---

## 3. BM25 模式 - 纯关键词检索

### 原理

```
query: "P7 晋升 条件"
         │
         ▼ 分词 + 倒排索引查询
    ┌────────────────────────────────────┐
    │ "P7"     → doc_ids: [3, 15, 42]   │
    │ "晋升"    → doc_ids: [3, 15, 28]   │
    │ "条件"    → doc_ids: [3, 42, 50]   │
    │                                    │
    │ BM25 打分:                          │
    │   doc_3:  score=18.5  ← 三词全中   │
    │   doc_15: score=12.3               │
    │   doc_42: score=8.1                │
    └────────────────────────────────────┘
```

### 特点

| 维度 | 评价 |
|------|------|
| 速度 | ⚡ 快（Elasticsearch 原生性能） |
| 语义理解 | ❌ 弱（"加班费" 和 "OT报酬" 视为完全不同的词） |
| 精确匹配 | ✅ 强（对编号、代码、专有名词精准） |
| 资源消耗 | 中 |

### 适用场景

- 查询包含明确的编号/代码（"P7"、"第15条"、"API-202"）
- 法律条文检索（"刑法第二百六十四条"）
- 需要精确词匹配的场景

## 4. Hybrid 模式 - 混合检索（推荐）🔥

### 原理

```
query: "P7级别加班费怎么算"
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐ ┌───────┐
│Vector │ │ BM25  │  两路并行检索
│ Top   │ │ Top   │
│  20   │ │  20   │
└──┬────┘ └──┬────┘
   │         │
   └────┬────┘
        ▼
   ┌─────────┐
   │   RRF   │  Reciprocal Rank Fusion
   │  融合排序 │
   └────┬────┘
        ▼
    Top 10 结果
```

Vector 擅长理解 "加班费怎么算"，BM25 精准命中 "P7"。
融合后两全其美：既有语义理解，又能精确匹配。

### 特点

| 维度 | 评价 |
|------|------|
| 速度 | 中等（两次检索并行，取最长耗时） |
| 语义理解 | ✅ 强 |
| 精确匹配 | ✅ 强 |
| 资源消耗 | 中 |
| 可用套餐 | Standard / Pro |

## 5. RRF 融合算法

### 5.1 公式

```
RRF_score(chunk) = Σ 1/(k + rank_i)
```

- `k`：平滑参数（默认 60），防止极端排名影响过大
- `rank_i`：chunk 在某一检索路中的排名（从 1 开始）

### 5.2 计算示例

```
chunk_A: vector_rank=1, bm25_rank=3
  score = 1/(60+1) + 1/(60+3) = 0.0164 + 0.0159 = 0.0323

chunk_B: vector_rank=2, bm25_rank=1
  score = 1/(60+2) + 1/(60+1) = 0.0161 + 0.0164 = 0.0325

chunk_C: vector_rank=5, bm25_rank=未命中
  score = 1/(60+5) + 0         = 0.0154
```

最终排序：B > A > C

### 5.3 代码实现

```python
# app/services/hybrid_search_service.py
def fuse_by_rrf(self, *, vector_chunks, bm25_chunks, rrf_k, top_n):
    merged = {}  # key: (kb_id, chunk_id)

    # 向量路: 按排名加入
    for rank, chunk in enumerate(vector_chunks, start=1):
        key = (chunk["kb_id"], chunk["chunk_id"])
        merged[key] = {**chunk, "vector_rank": rank, "bm25_rank": None}

    # BM25路: 合并或新增
    for rank, chunk in enumerate(bm25_chunks, start=1):
        key = (chunk["kb_id"], chunk["chunk_id"])
        if key in merged:
            merged[key]["bm25_rank"] = rank  # 双路命中!
        else:
            merged[key] = {**chunk, "vector_rank": None, "bm25_rank": rank}

    # 排序规则:
    # 1. RRF分数降序
    # 2. 双路命中优先 (hybrid > vector/bm25 only)
    # 3. 最小原始排名优先
    # 4. 稳定排序 (kb_id, chunk_id)
    for chunk in merged.values():
        score = 0
        if chunk["vector_rank"]: score += 1/(rrf_k + chunk["vector_rank"])
        if chunk["bm25_rank"]:   score += 1/(rrf_k + chunk["bm25_rank"])
        chunk["score"] = score

    fused.sort(key=lambda c: (
        -c["score"],                              # 分数
        -(c["vector_rank"] and c["bm25_rank"]),   # 双路命中加分
        min(c.get("vector_rank", 999), c.get("bm25_rank", 999)),  # 最小排名
    ))
    return fused[:top_n]
```

## 6. 完整检索流水线

一次 `/rag/retrieve` 请求实际执行的操作顺序：

```
Step 1: Query 处理
  ├── LLM改写 (可选, Pro): "咋退款" → "退款流程步骤"
  └── 同义词扩展 (可选): 追加KB配置的同义词

Step 2: 多路检索
  ├── Vector: embedding → pgvector → top_k
  └── BM25: Elasticsearch → top_k
  └── RRF融合 (hybrid模式)

Step 3: 候选过滤
  └── 去重、低信息量块过滤

Step 4: 图注入 (v2)
  ├── 引用目标 (chunk_relations)
  ├── 父章节 (parent_section_id)
  └── 相邻块 (order_index +- 1)

Step 5: ReRank 重排 (可选)
  └── Qwen3Rerank 精排 → 取 top_n

Step 6: 上下文扩展
  ├── 每个 anchor → 相邻块(previous/next)
  └── 父级章节内容

Step 7: Evidence 编排 (可选, Pro)
  └── LLM从候选中筛选并分组证据

Step 8: 返回结果
```
